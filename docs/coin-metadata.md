# مشخصات نمادها از نوبیتکس؛ لوگو از CoinGecko با کش محلی

**فارسی** · [English](coin-metadata.en.md)

> نام محصول nobitrader است؛ نام سرویس و مسیرهای قدیمی استقرار، شناسه‌های فنی واقعی‌اند و تغییر نکرده‌اند. [توضیح نام‌های فنی و نسخه‌بندی](releases.md).

## رفتار

- منبع اصلی نام، نماد، شبکه‌ها، وضعیت واریز/برداشت، دقت نمایش و مشخصات معاملاتی، **`/v2/options` نوبیتکس** است. همان درخواست موجود برنامه، بدون درخواست تکراری، هم به آداپتور قواعد معاملات و هم به کش متادیتا داده می‌دهد.
- CoinGecko از `/coins/markets` فقط **لوگو و نامِ جایگزین** را فراهم می‌کند. نام نوبیتکس، حتی اگر کش آن قدیمی باشد، بر نام CoinGecko اولویت دارد؛ زمان و `stale` این انتخاب آشکار است. اگر نام نوبیتکس موجود نباشد، نام CoinGecko با منبع صریح استفاده می‌شود.
- پاسخ مستند `/v2/options` فیلد لوگوی ارز ندارد؛ از مسیر داخلیِ حدسی یا آدرس تصویر غیرمستند نوبیتکس استفاده نمی‌کنیم.
- کش مشخصات صرفاً نمایشی است: فایل ذخیره‌شدهٔ قبلی در شروع برنامه دوباره به موتور سفارش اعمال نمی‌شود؛ مسیر موجود `apply_options` همچنان فقط پاسخ تازهٔ نوبیتکس را اعمال می‌کند. متادیتای CoinGecko هم وارد قیمت‌گذاری، سیگنال، فاندامنتال یا سفارش نمی‌شود.
- `server/coin_registry.json` شامل ۵۰ نگاشت صریح از نماد ارز پایه به شناسهٔ CoinGecko است. جست‌وجوی خودکار بر اساس نام کوتاه یا انتخاب اولین نتیجه وجود ندارد.
- هم شناسه و هم نماد پاسخ باید با نگاشت مطابقت داشته باشند. تغییر نام/نماد یک پروژه نیاز به بررسی صریح نگاشت دارد؛ لوگوی یک برند دیگر خودکار جایگزین نمی‌شود.
- تازه‌سازی مشخصات نوبیتکس هر **یک ساعت** است؛ خطای آن هر **۵ دقیقه** دوباره بررسی می‌شود. تازه‌سازی کامل لوگوهای CoinGecko هر **۲۴ ساعت** است؛ خطا و پوشش ناقص لوگوها هر **یک ساعت** دوباره بررسی می‌شود. در تلاش مجدد ساعتی، تصاویر تازهٔ موفق دوباره دانلود نمی‌شوند.
- دادهٔ سالم پیشین هنگام خطای شبکه، محدودیت درخواست یا خطای نوشتن حذف نمی‌شود. فایل تصویر و JSON با جایگزینی اتمیک نوشته می‌شوند و پس از restart خوانده می‌شوند.
- ارزهای خارج از فهرست ۵۰تایی لوگو نیز اگر در پاسخ نوبیتکس باشند، با نام و مشخصات واقعی‌شان در API برمی‌گردند؛ نبودن لوگو به معنی نبودن ارز نیست. اطلاعات شبکه/وضعیت فعالیت/قواعدِ موجودنبودن در پاسخ، `null` است؛ نه حدس و نه پیش‌فرض معاملاتی.
- مرورگر یک‌بار در شروع و سپس ساعتی فقط متادیتای کش‌شده را از سرور خودمان می‌خواند؛ درخواست کاربران هیچ دریافت تازه‌ای از سرویس بیرونی راه نمی‌اندازد.

ترتیب نمایش تصویر:

1. تصویر دانلودشده در کش سرور؛
2. یکی از ۴۰ لوگوی همراه پروژه؛
3. حروف کوتاه نماد، بدون ساختن لوگوی جعلی.

در نسخهٔ آفلاین موبایل فقط دو مرحلهٔ آخر موجود است. اگر فایل موبایل به سرور متصل باشد، استفاده از تصاویر کش به احراز هویت معتبر برای endpoint تصویر هم نیاز دارد؛ ناموفق بودن آن هیچ‌کدام از دو جایگزین محلی را از کار نمی‌اندازد.

## تنظیمات

در `server/.env` یا محیط واقعی سرویس (برای systemd: `/etc/nobi/nobi.env`):

```dotenv
NBX_COIN_METADATA_ENABLED=1
NBX_COIN_CACHE=/srv/nobi-data/coin-cache
# کلید Demo را فقط روی سرور وارد کنید؛ هرگز در HTML/مرورگر یا مخزن ننویسید.
# NBX_COINGECKO_API_KEY=
```

- `NBX_COINGECKO_API_KEY` کلید **Demo** است، نه Pro؛ فقط در هدر درخواست متادیتای API فرستاده می‌شود، نه query string و نه میزبان تصاویر.
- بدون کلید، دسترسی عمومی امتحان می‌شود؛ موفقیت آن تضمین‌شده نیست. خطا/۴۲۹ ⇒ حفظ کش و تلاش مجدد، نه نمایش وضعیت سبز.
- پیش‌فرض توسعه، `server/coin_cache` است (git-ignored). روی آروان مسیر باید داخل مسیر قابل‌نوشتن سرویس یعنی `/srv/nobi-data` باشد. نمونهٔ env و اسکریپت نصب این مسیر را تنظیم می‌کنند؛ نصب مجدد اسکریپت، مسیر کش را به env قدیمی هم اضافه می‌کند، بدون دست‌زدن به کلیدهای موجود.
- Docker Compose یک named volume مستقل برای این کش دارد.
- با `NBX_COIN_METADATA_ENABLED=0` فقط دریافت **CoinGecko** متوقف می‌شود؛ دریافت گزینه‌های عمومی نوبیتکس همچنان فعال است. کش قبلی و لوگوهای محلی قابل استفاده‌اند.
- پس از تغییر env، سرویس را restart کنید.

از ریشهٔ پروژه، روی ویندوز/لاراگون یا لینوکس:

```bash
python scripts/refresh_coin_metadata.py
```

این فرمان مشخصات نوبیتکس و لوگوهای CoinGecko را یک بار دریافت می‌کند و فقط تعداد ارزهای نوبیتکس، زمان/خطای دریافت آن و تعداد نگاشت‌ها، تصاویر کش‌شده، موارد قدیمی و کد خطا را چاپ می‌کند. خروجی صفر فقط برای موفقیت هر دو منبع و تازه‌سازی کامل لوگوها است؛ پوشش ناقص هم خروجی غیرصفر دارد، حتی اگر بعضی تصاویر با موفقیت ذخیره شده باشند. در استقرار آن را با همان کاربر و محیط سرویس اجرا کنید، نه با حساب root و مسیر پیش‌فرض توسعه.

## API داخلی و مشاهدهٔ سلامت

- `GET /api/coins`: ترکیب دو منبع با اولویت نوبیتکس. هر ردیف شامل `name_source`، `name_updated_at`، `name_stale` و `symbol_source` است. بخش `exchange` همان ارز، شامل شبکه‌ها، دقت نمایش، وضعیت فعالیت، منبع و زمان دریافت نوبیتکس است.
- `id` همان شناسهٔ CoinGecko برای **لوگو** است و برای ارزِ بدون نگاشت `null` می‌ماند؛ این شناسه نام یا هویت صرافی را بازنویسی نمی‌کند.
- `updated_at` و `stale` قبلی برای سازگاری مربوط به **لوگو** می‌مانند؛ `logo_source`، کد خطای لوگو و `image_url` محلی هم موجود است. تازه بودن نام نوبیتکس، لوگوی قدیمی را تازه جلوه نمی‌دهد.
- بخش بالادستی `exchange.trading_rules` شامل `minOrders`، `amountPrecisions` و `pricePrecisions` است. کلیدها و واحدهای اعلام‌شدهٔ نوبیتکس حفظ می‌شوند؛ مثلاً مقدار ریالیِ `rls` به تومان تغییر برچسب نمی‌خورد. مقادیر عددی به صورت رشته‌اند تا تبدیل نمایشی دقت را از بین نبرد.
- `GET /api/coins/{id}/logo`: فقط تصویر موجود در کش، نه proxy دلخواه. مورد ناشناخته/نامعتبر ⇒ ۴۰۴.
- هر دو endpoint تابع همان دروازهٔ ورود داشبورد هستند. کلید CoinGecko یا URL خارجی تصویر در پاسخ قرار نمی‌گیرد.
- تب تنظیمات، کارت جداگانهٔ `nobitex_metadata` سلامت و تعداد ارزهای مشخصات صرافی را نشان می‌دهد؛ کارت `coin_metadata` مستقل از آن تعداد تصاویر کش‌شده را نشان می‌دهد. حالتِ اندازه‌گیری‌نشده «نامعلوم» است؛ پوشش ناقص یا کش قدیمی، زرد است، نه سبز.
- `last_success` زمان آخرین تازه‌سازی **کامل** است؛ در پوشش ناقص، زمان واقعی هر ارز را در `updated_at` ببینید.

کد خطاهای هر ارز:

| کد | معنی |
|---|---|
| `coin_not_returned` | سرویس، شناسهٔ ثبت‌شده را برنگردانده است |
| `identity_mismatch` | نماد پاسخ با نماد مورد انتظار تطابق ندارد؛ جایگزینی خودکار ممنوع است |
| `invalid_metadata` | نام یا آدرس تصویر نامعتبر است |
| `image_unavailable` | دریافت، قالب یا ذخیرهٔ تصویر موفق نبوده است |

## محدودیت‌های امنیتی و منبع

- میزبان تصاویر فقط `coin-images.coingecko.com` و `assets.coingecko.com`، با HTTPS و مسیر `/coins/images/` است؛ redirect دنبال نمی‌شود.
- تصاویر حداکثر ۵۱۲ کیبی‌بایت و فقط PNG/JPEG/WebP هستند؛ SVG بیرونی، HTML و محتوای ناشناخته پذیرفته نمی‌شوند. پاسخ‌ها `nosniff` دارند.
- پاسخ متادیتا حداکثر ۲ میبی‌بایت است. نام فایل فقط از شناسهٔ نگاشت معتبر ساخته می‌شود؛ کلاینت نمی‌تواند URL یا مسیر فایل به سرور تحمیل کند.
- کلیدها، متن خطای upstream و بدنهٔ پاسخ‌های ناموفق لاگ نمی‌شوند. وضعیت خطا فقط کدهای ثابت دارد.
- لوگوهای CoinGecko دارایی پروژه‌های مربوط‌اند؛ این دانلود به معنی اعطای مجوز CC0 به آن‌ها نیست. مجوز CC0 پوشهٔ `assets/coins` فقط مربوط به مجموعهٔ fallback محلی است. برای توزیع مجدد تصاویر کش‌شده شرایط CoinGecko و حقوق علائم تجاری را بررسی کنید؛ کش در Git ثبت نمی‌شود.

مستندات سرویس: https://docs.coingecko.com/reference/coins-markets

## آزمون‌های قابل تکرار

```bash
python -m pytest -q server/tests/test_coin_metadata.py server/tests/test_nobitex_metadata.py
npm run build
npm run test:icons
```

آزمون‌های خودکار upstream را شبیه‌سازی می‌کنند تا تکرارپذیر باشند. آزمون زندهٔ اجراشده در این محیط در ۲۰۲۶-۱۰-۲۱، **۴۹ تصویر از ۵۰ نگاشت** را ذخیره کرد. برای `TON`، شناسهٔ ثبت‌شده پاسخی با نماد متفاوت برگرداند؛ به‌عمد `identity_mismatch` ثبت شد و لوگوی آن به‌جای حدس‌زدن برند، از مسیر fallback می‌آید. این مشاهدهٔ زمان آزمون است، نه تضمین پوشش آینده یا تأیید روی سرور شما.

### محدودیت آزمون زندهٔ نوبیتکس

در اجرای این تغییر در ۲۰۲۶-۱۰-۲۱، درخواست زندهٔ `/v2/options` از محیط توسعه ناموفق بود (`refresh_failed`، صفر ارزِ تأییدشده، زمان دریافت `null`). بنابراین دریافت زندهٔ مشخصات نوبیتکس در این محیط تأیید نشده است؛ هیچ نام، شبکه یا مشخصات ساختگی جای آن ذخیره نشده است. اولویت منابع، حفظ کش، خروجی API و اتصال درخواست مشترک به موتور قواعد با تست‌های تکرارپذیر و پاسخ‌های نمونه آزموده می‌شوند. اجرای `python scripts/refresh_coin_metadata.py` روی سیستم کاربر/سرور، نتیجهٔ واقعی اتصال همان‌جا را نشان می‌دهد.

مرجع مشخصات نوبیتکس: https://apidocs.nobitex.ir/openapi/options.yaml
