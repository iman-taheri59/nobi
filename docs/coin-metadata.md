# مشخصات و لوگوی نمادها — CoinGecko با کش محلی

## رفتار

- کارگر پس‌زمینهٔ سرور نام، شناسه، نماد و لوگو را از `/coins/markets` دریافت می‌کند؛ این داده‌ها **صرفاً نمایشی** هستند و وارد قیمت‌گذاری، سیگنال، فاندامنتال یا سفارش نمی‌شوند.
- `server/coin_registry.json` شامل ۵۰ نگاشت صریح از نماد ارز پایه به شناسهٔ CoinGecko است. جست‌وجوی خودکار بر اساس نام کوتاه یا انتخاب اولین نتیجه وجود ندارد.
- هم شناسه و هم نماد پاسخ باید با نگاشت مطابقت داشته باشند. تغییر نام/نماد یک پروژه نیاز به بررسی صریح نگاشت دارد؛ لوگوی یک برند دیگر خودکار جایگزین نمی‌شود.
- تازه‌سازی کامل هر ۲۴ ساعت است؛ خطا و پوشش ناقص هر یک ساعت دوباره بررسی می‌شود. در تلاش مجدد ساعتی، تصاویر تازهٔ موفق دوباره دانلود نمی‌شوند.
- دادهٔ سالم پیشین هنگام خطای شبکه، محدودیت درخواست یا خطای نوشتن حذف نمی‌شود. فایل تصویر و JSON با جایگزینی اتمیک نوشته می‌شوند و پس از restart خوانده می‌شوند.
- مرورگر یک‌بار در شروع و سپس ساعتی فقط متادیتای کش‌شده را از سرور خودمان می‌خواند؛ درخواست کاربران هیچ دریافت تازه‌ای از سرویس بیرونی راه نمی‌اندازد.

ترتیب نمایش تصویر:

1. تصویر دانلودشده در کش سرور؛
2. یکی از ۴۰ لوگوی همراه پروژه؛
3. حروف کوتاه نماد، بدون ساختن لوگوی جعلی.

در نسخهٔ آفلاین موبایل فقط دو مرحلهٔ آخر موجود است. اگر فایل موبایل به سرور متصل باشد، استفاده از تصاویر کش به احراز هویت معتبر برای endpoint تصویر هم نیاز دارد؛ ناموفق بودن آن هیچ‌کدام از دو جایگزین محلی را از کار نمی‌اندازد.

## تنظیمات

در `server/.env` یا محیط واقعی سرویس (برای systemd: `/etc/nobi/nobi.env`):

```dotenv
NBX_COIN_METADATA_ENABLED=1
NBX_COIN_CACHE=/srv/nobi-data/coin-cache
# کلید Demo را فقط روی سرور وارد کنید؛ هرگز در HTML/مرورگر یا مخزن ننویسید.
# NBX_COINGECKO_API_KEY=
```

- `NBX_COINGECKO_API_KEY` کلید **Demo** است، نه Pro؛ فقط در هدر درخواست متادیتای API فرستاده می‌شود، نه query string و نه میزبان تصاویر.
- بدون کلید، دسترسی عمومی امتحان می‌شود؛ موفقیت آن تضمین‌شده نیست. خطا/۴۲۹ ⇒ حفظ کش و تلاش مجدد، نه نمایش وضعیت سبز.
- پیش‌فرض توسعه، `server/coin_cache` است (git-ignored). روی آروان مسیر باید داخل مسیر قابل‌نوشتن سرویس یعنی `/srv/nobi-data` باشد. نمونهٔ env و اسکریپت نصب این مسیر را تنظیم می‌کنند؛ نصب مجدد اسکریپت، مسیر کش را به env قدیمی هم اضافه می‌کند، بدون دست‌زدن به کلیدهای موجود.
- Docker Compose یک named volume مستقل برای این کش دارد.
- با `NBX_COIN_METADATA_ENABLED=0` دریافت بیرونی متوقف می‌شود؛ کش قبلی و لوگوهای محلی همچنان قابل استفاده‌اند.
- پس از تغییر env، سرویس را restart کنید.

از ریشهٔ پروژه، روی ویندوز/لاراگون یا لینوکس:

```bash
python scripts/refresh_coin_metadata.py
```

این فرمان یک تازه‌سازی اجباری انجام می‌دهد و فقط تعداد نگاشت‌ها، تصاویر کش‌شده، موارد قدیمی و کد خطا را چاپ می‌کند. خروجی صفر فقط برای تازه‌سازی کامل است؛ پوشش ناقص هم خروجی غیرصفر دارد، حتی اگر بعضی تصاویر با موفقیت ذخیره شده باشند. در استقرار آن را با همان کاربر و محیط سرویس اجرا کنید، نه با حساب root و مسیر پیش‌فرض توسعه.

## API داخلی و مشاهدهٔ سلامت

- `GET /api/coins`: نام، نماد، شناسه، زمان دریافت، `stale`، کد خطای هر ارز و `image_url` **محلی**.
- `GET /api/coins/{id}/logo`: فقط تصویر موجود در کش، نه proxy دلخواه. مورد ناشناخته/نامعتبر ⇒ ۴۰۴.
- هر دو endpoint تابع همان دروازهٔ ورود داشبورد هستند. کلید CoinGecko یا URL خارجی تصویر در پاسخ قرار نمی‌گیرد.
- تب تنظیمات، کارت `coin_metadata` تعداد تصاویر کش‌شده را نشان می‌دهد. حالتِ اندازه‌گیری‌نشده «نامعلوم» است؛ پوشش ناقص یا کش قدیمی، زرد است، نه سبز.
- `last_success` زمان آخرین تازه‌سازی **کامل** است؛ در پوشش ناقص، زمان واقعی هر ارز را در `updated_at` ببینید.

کد خطاهای هر ارز:

| کد | معنی |
|---|---|
| `coin_not_returned` | سرویس، شناسهٔ ثبت‌شده را برنگردانده است |
| `identity_mismatch` | نماد پاسخ با نماد مورد انتظار تطابق ندارد؛ جایگزینی خودکار ممنوع است |
| `invalid_metadata` | نام یا آدرس تصویر نامعتبر است |
| `image_unavailable` | دریافت، قالب یا ذخیرهٔ تصویر موفق نبوده است |

## محدودیت‌های امنیتی و منبع

- میزبان تصاویر فقط `coin-images.coingecko.com` و `assets.coingecko.com`، با HTTPS و مسیر `/coins/images/` است؛ redirect دنبال نمی‌شود.
- تصاویر حداکثر ۵۱۲ کیبی‌بایت و فقط PNG/JPEG/WebP هستند؛ SVG بیرونی، HTML و محتوای ناشناخته پذیرفته نمی‌شوند. پاسخ‌ها `nosniff` دارند.
- پاسخ متادیتا حداکثر ۲ میبی‌بایت است. نام فایل فقط از شناسهٔ نگاشت معتبر ساخته می‌شود؛ کلاینت نمی‌تواند URL یا مسیر فایل به سرور تحمیل کند.
- کلیدها، متن خطای upstream و بدنهٔ پاسخ‌های ناموفق لاگ نمی‌شوند. وضعیت خطا فقط کدهای ثابت دارد.
- لوگوهای CoinGecko دارایی پروژه‌های مربوط‌اند؛ این دانلود به معنی اعطای مجوز CC0 به آن‌ها نیست. مجوز CC0 پوشهٔ `assets/coins` فقط مربوط به مجموعهٔ fallback محلی است. برای توزیع مجدد تصاویر کش‌شده شرایط CoinGecko و حقوق علائم تجاری را بررسی کنید؛ کش در Git ثبت نمی‌شود.

مستندات سرویس: https://docs.coingecko.com/reference/coins-markets

## آزمون‌های قابل تکرار

```bash
python -m pytest -q server/tests/test_coin_metadata.py
npm run build
npm run test:icons
```

آزمون‌های خودکار upstream را شبیه‌سازی می‌کنند تا تکرارپذیر باشند. آزمون زندهٔ اجراشده در این محیط در ۲۰۲۶-۱۰-۲۱، **۴۹ تصویر از ۵۰ نگاشت** را ذخیره کرد. برای `TON`، شناسهٔ ثبت‌شده پاسخی با نماد متفاوت برگرداند؛ به‌عمد `identity_mismatch` ثبت شد و لوگوی آن به‌جای حدس‌زدن برند، از مسیر fallback می‌آید. این مشاهدهٔ زمان آزمون است، نه تضمین پوشش آینده یا تأیید روی سرور شما.
