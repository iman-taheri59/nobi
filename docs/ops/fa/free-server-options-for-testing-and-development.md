# راهنمای استفاده از سرورها و سرویس‌های رایگان برای تست و توسعه

> مکمل ADR-0010. وضعیت: آخرین به‌روزرسانی بر اساس داده‌های فوریه ۲۰۲۶.
> **نتيجه کوتاه:** بله — برای توسعه، تست و معامله کاغذی (Paper Trading) تقریباً تمام پشته را می‌توان رایگان اجرا کرد. برای معامله زنده، سرور رایگان توصیه نمی‌شود.

### ارزیابی برای پروژه ما
- سطح ۱ ADR-0010 (معامله کاغذی) به 2 vCPU / 4 GB نیاز دارد → **Oracle Free (2 OCPU/12 GB) با حاشیه کامل پوشش می‌دهد** و تنها گزینه رایگانِ واقعاً عملیاتی است.
- GCP e2-micro با ۱ گیگابایت RAM برای کل پشته (Postgres + Redis + Python) کافی نیست؛ فقط برای پروب مانیتورینگ مناسب است.
- هیچ VPS رایگان داخلی (ایرانی) پایدار شناخته‌شده‌ای وجود ندارد؛ برخی ارائه‌دهندگان داخلی فقط دوره آزمایشی چندروزه دارند.

## ۲. پشته رایگان پیشنهادی به تفکیک کامپوننت

| کامپوننت پروژه | گزینه رایگان | توضیح |
|---|---|---|
| **گره اصلی (ربات + زمان‌بند + دیتابیس + Redis + Grafana)** | Oracle Cloud Always Free (Docker Compose) | کل پشته سطح ۱ روی یک ماشین ARM |
| محیط توسعه در ابر | GitHub Codespaces (ساعات رایگان ماهانه) | جایگزین/مکمل سیستم شخصی |
| CI/CD | GitHub Actions (رایگان برای مخازن عمومی/خصوصی با سقف) | Lint، تست، تست‌های قراردادی آداپتور |
| بک‌تست سنگین و تحقیق | Google Colab / Kaggle Notebooks (رایگان) | سطح ۳ در ADR-0010 را عملاً رایگان پوشش می‌دهد |
| دیتابیس Postgres مدیریت‌شده (اختیاری) | Neon / Supabase (سطح رایگان) | برای توسعه سبک؛ Supabase اکستنشن TimescaleDB را هم پشتیبانی می‌کند — ولی در تولید، DB را کنار ربات نگه دارید |
| Redis مدیریت‌شده (اختیاری) | Upstash (سطح رایگان با سقف روزانه) | توسعه سبک؛ سقف روزانه برای عملیات کافی نیست |
| پروب مانیتورینگ خارج از میزبان | UptimeRobot / Healthchecks.io (رایگان) | ضربان قلب ربات + هشدار قطعی گره اصلی |
| ذخیره‌سازی بکاپ | حافظه شخصی / فضای ابری رایگان (max ~۱۵ GB) | مقصد dump روزانه دیتابیس |

## ۳. نکات و خطرهای مخصوص پروژه ما (ضروری بخوانید)

1. **معماری ARM64:** ماشین Oracle A1 معماری ARM دارد. تمام وابستگی‌های اصلی ما (Python, pandas, numpy, Redis, TimescaleDB, Grafana) دارای ایمیج/پکیج ARM64 هستند و سازگاری مشکلی ندارد؛ `TA-Lib` را از سورس کامپایل کنید. قبل از پذیرش نهایی، یک Smoke Test کامل Docker Build روی دستگاه/ایمیج ARM انجام دهید.
2. **ملاحظات جغرافیایی نوبیتکس:** همه VPSهای رایگان خارج از ایران‌اند. پیش از اتکا به آن‌ها، اتصال به `apiv2.nobitex.ir` را از گره انتخاب‌شده تست کنید (تأخیر + پایداری + رفتار در ساعات اوج). برای گام معاملاتی دقیقه‌ای، تأخیر خارج‌از‌ایران معمولاً قابل‌قبول است، اما دسترسی/ثبات را ابتدا با اسکریپت ساده `/market/stats` به مدت چند روز سنجه کنید.
3. **IP ثابت و بازپس‌گیری (Reclaim):** ماشین‌های بلااستفاده Oracle می‌توانند بازپس‌گیری شوند و IPهای موقت با Stop/Start تغییر می‌کنند. برای تست مشکلی نیست؛ برای کلید API نوبیتکس از گزینه **Reserved Public IP** (در محدوده رایگان) استفاده یا کلید را به IP نبندید — فقط در مرحله تست/کاغذی.
4. **سیاست امنیتی کلیدها:** روی سرویس‌های رایگان **هرگز** کلید با مجوز TRADE واقعی قرار ندهید. فقط کلید آزمایشی با موجودی خرد یا حالت Paper. شناسه‌های رایگان ممکن است ثبت/نظارت متفاوتی روی ورودی‌ها داشته باشند.
5. **پایداری برای ۲۴/۷:** سرویس‌های رایگان PaaS (Render/Railway) با عدم استفاده Sleep می‌کنند و زمان‌بند کندل را مختل می‌کنند → فقط Oracle VPS (یا مشابه همیشه‌روشن) برای اجرای ربات؛ بقیه سرویس‌ها برای اجزای فرعی.
6. **بکاپ:** در محیط رایگان هم قانون ADR-0009 پابرجاست — dump روزانه دیتابیس به مقصدی خارج از گره (مثلاً فضای ابری رایگان یا NAS خانگی)، چون گارانتی ماندگاری ماشین رایگان وجود ندارد.

## ۴. تصمیم و توصیه عملیاتی

- ✅ **توسعه و تست (Tier 0/1):** کاملاً رایگان شدنی. ترکیب پیشنهادی: **Oracle Free به‌عنوان گره اصلی + GitHub Actions برای CI + Colab/Kaggle برای بک‌تست + UptimeRobot برای پروب.**
- ✅ **معامله کاغذی (حداقل ۳۰ روز روی داده زنده):** روی Oracle Free قابل اجراست؛ دیتای ارزشمندی برای دروازه ارتقا به زنده تولید می‌کند.
- ⚠️ **پیش از Go-Live:** بررسی نهایی تأخیر/ثبات از لوکیشن رایگان؛ اگر رضایت‌بخش نبود، فقط سرور تولید (25–40 دلار در ماه) پولی شود؛ بقيه پشته می‌تواند رایگان بماند.
- ❌ **معامله زنده با سرمایه واقعی روی سرور رایگان:** توصیه نمی‌شود (ریسک بازپس‌گیری ماشین، نبود SLA، سیاست‌های Idle، امنیت کلید). خرج ماهانه یک VPS پولی کم‌هزینه‌تر از یک خطای اجرایی است.

## ۵. چک‌لیست راه‌اندازی رایگان (Quick Start)

1. ساخت اکانت Oracle Cloud ← ایجاد VM.Standard.A1 (2 OCPU / 12 GB) ← انتخاب Ubuntu ARM64.
2. Reserved IP رایگان اختصاص دهید (در همان اکانت).
3. نصب Docker + docker-compose؛ کلون مخزن؛ اجرای `config` با حالت `paper`.
4. فایروال: فقط SSH از IP شما + خروجی آزاد؛ هیچ پورت دیتابیس/Redis به بیرون.
5. قبل از هرچیز: اسکریپت سلامت اتصال به نوبیتکس (هر ساعت به‌مدت ۷۲ ساعت) اجرا و نتیجه را در روندنما ثبت کنید.
6. راه‌اندازی پروب رایگان (UptimeRobot) روی اندپوینت `/health` ربات.
7. cron بکاپ روزانه به مقصد خارج از گره.
