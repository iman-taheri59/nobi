# ADR-0041 — ماتریس دسترسی سامانه پس از بازبینی کامل

[English](../en/ADR-0041-system-access-matrix.md) · **فارسی**

**وضعیت:** پذیرفته — در ۱٫۴٫۴ اعمال شد
**تاریخ:** ۲۰۲۶-۱۰-۲۵

## زمینه

پس از owner-only شدن کاربران و خطایابی، routeهای باقی‌مانده بازبینی شدند. تنظیمات runtime شامل مسیرها و presence رازها بود و برای viewer/operator باز می‌ماند؛ audit شامل context عملیاتی و IP بود؛ readهای private exchange با dependency مخصوص mutation و CSRF محافظت می‌شدند که از نظر معنا اشتباه بود.

## تصمیم و ماتریس

| حوزه | viewer | operator | owner | machine token |
|---|---|---|---|---|
| بازار، سیگنال، گزارش و paper state | خواندن | خواندن | خواندن | خواندن طبق middleware |
| paper order، halt/resume، exec mode، backtest، journal maintenance | رد | mutation+CSRF | mutation+CSRF | طبق allowlist قدیمی `require_client` |
| audit عملیاتی و notify status | رد | خواندن | خواندن | رد |
| live status/evidence/private orders | رد | خواندن | خواندن | رد |
| live dry-run/cancel/reconcile | رد | mutation+CSRF | mutation+CSRF | طبق `require_client` |
| settings runtime، cache internals، Telegram credential probe | رد | رد | owner؛ mutation+CSRF | رد |
| کاربران، نصب، عملیات privileged و خطایابی | رد | رد | owner؛ mutation+CSRF | رد |
| live placement | رد | فقط operator منتخب با policy+CSRF | owner+CSRF | رد |

- helper جدید `require_operator` فقط session فعال operator/owner را می‌پذیرد و برای GETهای عملیاتی CSRF نمی‌خواهد.
- تب Settings و کارت audit متناسب با نقش پنهان می‌شوند؛ backend مستقل enforce می‌کند.
- تنظیمات همچنان read-only است، اما read-only بودن به معنی عمومی بودن context استقرار نیست.
- machine token نقش انسانی به ارث نمی‌برد و به حوزه‌های private/admin دسترسی ندارد.

## موارد بدون تغییر

viewer برای مشاهده داده معاملاتی، وضعیت paper، نتایج و گزارش‌ها حفظ شد. operator همچنان مسئول عملیات روزمره paper/backtest/journal است. endpoint دریافت خودکار خطای مرورگر و endpoint health طبق سیاست قبلی باقی ماندند.
