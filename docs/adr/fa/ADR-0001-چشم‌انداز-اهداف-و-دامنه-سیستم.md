# ADR-0001: چشم‌انداز، اهداف و دامنه سیستم

- **وضعیت:** پذیرفته‌شده — منشور پروژه (Accepted, charter)
- **تاریخ:** 2026-02-14
- **تصمیم‌گیرندگان:** مالک پروژه، معمار فنی
- **ADRهای مرتبط:** 0002، 0007، 0008

---

## ۱. زمینه

هدف، ساخت یک ربات معامله‌گر خودکار حرفه‌ای، دقیق و کامل برای صرافی **نوبیتکس** (بزرگ‌ترین صرافی رمزارز ایران، با آدرس پایه `https://apiv2.nobitex.ir`) است. ربات باید:

1. تمام رمزارزهای لیست‌شده در نوبیتکس (بازارهای `IRT` = تومان و بازارهای `USDT`) را با **تحلیل تکنیکال (TA)** و **تحلیل فاندامنتال (FA)** بررسی کند.
2. با استفاده از **API رسمی نوبیتکس** سفارش خرید و فروش ثبت کند.
3. به‌صورت خودکار **بهترین گزینه‌های معاملاتی** را رتبه‌بندی و انتخاب کند.
4. معاملات سودآور انجام دهد و در عین حال سرمایه را تحت قواعد سخت‌گیرانه و قابل پیکربندی مدیریت ریسک حفظ کند.

نکته مهم: هیچ سیستمی نمی‌تواند سود را تضمین کند. این ADR چشم‌انداز را تعریف می‌کند؛ ADRهای بعدی مهندسیِ لازم برای بیشینه‌سازی احتمال موفقیت و محدودکردن زیان را مشخص می‌کنند.

## ۲. اهداف

| شناسه | هدف | معیار موفقیت |
|---|---|---|
| G1 | پوشش کامل دنیای قابل معامله نوبیتکس (جفت‌های تومانی و تتری) | اسکن ۱۰۰٪ بازارهای فعال در هر چرخه |
| G2 | تولید سیگنال ترکیبی TA + FA با یک امتیاز واحد (۰ تا ۱۰۰) برای هر دارایی | امتیازدهی قطعی و قابل بک‌تست |
| G3 | اجرای کاملاً خودکار از طریق API رسمی نوبیتکس (اسپات) | تطابق کامل چرخه‌حیات سفارش با وضعیت واقعی صرافی |
| G4 | اولویت حفظ سرمایه: کلید اضطراری (Kill Switch)، توقف در افت سرمایه، سقف ریسک هر معامله و سبد | محدودیت‌های قابل تنظیم که پیش از هر سفارش در کد اعمال می‌شوند |
| G5 | استقرار امن: بک‌تست ← معامله کاغذی ← زنده با حجم خرد ← زنده کامل | دروازه‌های ارتقا با آستانه‌های قابل سنجش |
| G6 | پایش‌پذیری و هشداردهی کامل | هر تصمیم و سفارش، لاگ، نوتیفیکیشن و قابل حسابرسی |

## ۳. موارد خارج از دامنه (Non-Goals)

- معاملات فرکانس بالا / مارکت‌میکینگ (API نوبیتکس مبتنی بر REST/Polling است و HFT شدنی نیست).
- معاملات مارجین/فیوچرز/اهرم (فاز ۱ فقط اسپات؛ اندپوینت‌های مارجین وجود دارند اما به تعویق افتاده‌اند).
- خودکارسازی برداشت دارایی (ربات هرگز مجوز برداشت نخواهد داشت).
- آربیتراژ بین‌صرافی (فاز آینده).
- ورود/خروج خودکار فیات.

## ۴. محدودیت‌ها

| محدودیت | اثر |
|---|---|
| محدودیت نرخ API نوبیتکس (مثلاً orderbook v3 حدود ۳۰۰ درخواست در دقیقه) | زمان‌بندی درخواست‌ها با Token Bucket |
| پرمیوم قیمتی بازار تومانی نسبت به تتر | مقایسه سیگنال‌ها باید «پرمیوم-آگاه» باشد |
| دفتر سفارش نیمه‌کم‌عمق برای آلت‌کوین‌های کوچک | فیلتر نقدشوندگی + مدل‌سازی لغزش (Slippage) الزامی |
| مقررات و شرایط استفاده نوبیتکس | کلیدها باید فقط مجوز معامله (TRADE) داشته باشند |
| قطعی‌های دوره‌ای API و نگهداری | Circuit Breaker + تخریب تدریجی سرویس |

## ۵. تصمیم

اتخاذ برنامه چهارفازی:

- **فاز ۰ – زیرساخت:** کلاینت صرافی، دریافت و ذخیره داده، موتور بک‌تست.
- **فاز ۱ – موتور تکنیکال + معامله کاغذی:** موتور اندیکاتورها و سیگنال‌ها، اجرای کاغذی، داشبوردها.
- **فاز ۲ – موتور فاندامنتال + تلفیق سیگنال:** امتیازدهی بنیادی، امتیاز ترکیبی، رتبه‌بندی دارایی‌ها.
- **فاز ۳ – زنده با حجم خرد:** کلید API فقط-معاملاتی، حداکثر ۱٪ سرمایه در هر معامله، کلید اضطراری مسلح.
- **فاز ۴ – بهره‌برداری کامل:** حجم‌دهی مقیاس‌پذیر در چارچوب سقف‌ها، ارزیابی و بهینه‌سازی مداوم.

**حالت پیش‌فرض، معامله کاغذی (Paper Trading) است.** معامله زنده نیازمند پرچم صریح در پیکربندی + چک‌لیست (ADR-0009) است.

## ۶. پیامدها

**مثبت:** ریسک افزایشی؛ هر فاز یک خروجی قابل آزمون دارد؛ پیش از وجود شواهد، هرگز سرمایه واقعی در معرض خطر نیست.
**منفی:** رسیدن به نسخه زنده کُندتر است؛ نیازمند انضباط در احترام به دروازه‌های ارتقا.

## ۷. سلب مسئولیت اخلاقی و حقوقی

این نرم‌افزار یک ابزار پشتیبانی تصمیم و اجراست، نه وعده سود. کاربر باید از شرایط استفاده نوبیتکس و مقررات مربوط تبعیت کند. همه اطلاعات محرمانه به‌صورت محلی می‌مانند؛ مجوز برداشت عمداً خارج از دامنه است.

## ۸. معیارهای موفقیت کلی

- بک‌تست: ضریب سود (Profit Factor) بیش از ۱٫۳، حداکثر افت سرمایه کمتر از ۱۵٪، حداقل ۱۰۰ معامله.
- کاغذی: حداقل ۳۰ روز روی داده زنده، PF بالای ۱٫۲.
- عملیات: موفقیت جاب‌ها ≥ ۹۹٪، تأخیر میانگین سیگنال-تا-سفارش کمتر از ۵ ثانیه.
