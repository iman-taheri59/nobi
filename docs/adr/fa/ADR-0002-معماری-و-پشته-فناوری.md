# ADR-0002: معماری سطح بالا و پشته فناوری

- **وضعیت:** پیشنهادی (Proposed)
- **تاریخ:** 2026-02-14
- **تصمیم‌گیرندگان:** معمار فنی
- **ADRهای مرتبط:** 0001، 0003، 0004

---

## ۱. زمینه

سیستم باید داده بازار را دریافت کند، سیگنال‌های TA و FA را محاسبه کند، آن‌ها را به تصمیم معامله تبدیل کند، ریسک را مدیریت کند و سفارش‌ها را بدون نظارت انسانی اجرا کند — به‌صورت پایدار. بار اصلی محاسبات عددی (اندیکاتورها، بک‌تست Walk-Forward) به‌علاوه I/O (Polling روی REST) است. پایتون برای این کلاس از کار، قوی‌ترین اکوسیستم را دارد.

## ۲. تصمیم

### ۲.۱ زبان و محیط اجرا
- **Python 3.12+** با Type Checking کامل (mypy) و مدیریت وابستگی با `uv`/`poetry`.

### ۲.۲ کتابخانه‌های اصلی
| نیاز | انتخاب | دلیل |
|---|---|---|
| دیتافریم | `pandas`, `numpy` | استاندارد واقعی پایپ‌لاین اندیکاتورها |
| اندیکاتورها | `pandas-ta` (اصلی)، wrapper اختیاری `TA-Lib` | پوشش بیش از ۱۰۰ اندیکاتور |
| بک‌تست | `vectorbt` (برداری) + موتور رویدادمحور اختصاصی | تحقیق سریع + شبیه‌سازی واقعی سفارش |
| HTTP ناهمزمان | `httpx` + `tenacity` | Timeout، Retry، مدیریت نرخ |
| زمان‌بندی | `APScheduler` (توکار) یا Celery Beat در صورت مقیاس | جاب‌های به‌ازای هر تایم‌فریم |
| کش / صف | `Redis` | وضعیت داغ، سطل‌های نرخ، رویدادهای pub/sub |
| ذخیره‌سازی | **PostgreSQL + TimescaleDB** (Hypertable برای کندل‌ها)، `parquet` برای دیتاست‌های تحقیقاتی | بومیِ سری‌های زمانی + انطباق با بک‌تست |
| پیکربندی / اعتبارسنجی | `pydantic-settings` | پیکربندی تایپ‌شده و محیط‌محور |
| API کنترل / UI | `FastAPI` + داشبورد مینیمال | شروع/توقف، حالت، نمای پوزیشن‌ها |
| نوتیفیکیشن | Telegram Bot API | رایج‌ترین ابزار هشدار عملیاتی در ایران |
| متریک‌ها | `prometheus-client` + Grafana | تأخیر، سود/زیان، خطاها |
| بسته‌بندی | Docker / docker-compose | استقرار تک‌دستوری |

### ۲.۳ چیدمان ماژول‌ها (مونورپوی ماژولار)
```
src/
  exchange/        # آداپتور نوبیتکس (احراز هویت، REST، نرمال‌سازی) — ADR-0003
  data/            # دریافت داده، ذخیره کندل، کنترل کیفیت — ADR-0004
  ta/              # رجیستری اندیکاتورها، موتور سیگنال TA — ADR-0005
  fa/              # منابع داده بنیادی، امتیازدهی FA — ADR-0006
  decision/        # امتیاز ترکیبی، رتبه‌بندی، انتخاب — ADR-0007
  risk/            # حجم‌دهی، استاپ، کلیدهای اضطراری — ADR-0008
  execution/       # مدیر سفارش، بروکرهای کاغذی/زنده — ADR-0009
  backtest/        # موتورها، Walk-Forward، گزارش‌ها
  observability/   # لاگ، متریک، هشدار
  config/          # تنظیمات، Feature Flagها
```

### ۲.۴ جریان داده (در هر چرخه)
```
Nobitex REST → دریافت → TimescaleDB → سیگنال TA ─┐
منابع FA → امتیاز FA ────────────────────────────┼→ موتور تصمیم → موتور ریسک → مدیر سفارش → market/orders/add
                                Redis (وضعیت داغ)┘                  ↘ کلید اضطراری (دروازه پیش از معامله)
```

## ۳. گزینه‌های بررسی‌شده

| گزینه | رأی | دلیل |
|---|---|---|
| فول‌استک Node.js/TS | رد (به‌عنوان اصلی) | اکوسیستم ضعیف‌تر TA/بک‌تست/ML |
| معماری میکروسرویس | رد (در نسخه ۱) | بار عملیاتی بیش از فایده برای یک ربات |
| SDKهای غیررسمی نوبیتکس | رد (به‌عنوان وابستگی اصلی) | ریسک اعتماد و به‌روزرسانی؛ آداپتور نازک خودمان را می‌سازیم |
| استفاده از `ccxt` به‌عنوان کانکتور اصلی | رد | پشتیبانی نوبیتکس جزئی/کهنه است؛ پیاده‌سازی مستقیم بر اساس مستندات رسمی |

## ۴. پیامدها

**مثبت:** پشته تحلیلی درجه‌یک؛ انطباق آموزش/سرو؛ ماژول‌های قابل آزمون؛ بدون وابستگی SaaS خارجی برای کلیدها.

**منفی:** کلاینت اختصاصی نوبیتکس یعنی هزینه نگهداری هنگام تغییر API (تسکین: آداپتور نازک + تست‌های قراردادی/Contract Tests).
