# ADR-0038 — ثبت سفارش واقعی فقط برای مالک و پس از promotion gate

[English](../en/ADR-0038-owner-live-order-placement.md) · **فارسی**

**وضعیت:** پذیرفته — در ۱٫۴٫۰ پیاده شد؛ فعال‌سازی عملی منتظر soak واقعی است
**تاریخ:** ۲۰۲۶-۱۰-۲۵

## تصمیم

- `POST /api/live/place` فقط session نقش owner همراه CSRF می‌پذیرد؛ API token یا operator کافی نیست.
- route حتی در حالت disabled قابل کشف است، اما تا `NBX_LIVE_MODE=live`، credential معتبر و interlock محیطی fail-closed می‌ماند.
- هر درخواست عبارت دقیق `PLACE-REAL-ORDER` و idempotency key تازه می‌خواهد.
- promotion gate داخل سرور حداقل ۳۰ نمونه dry-run در ۵ روز متمایز و صفر outcome مبهم را بررسی می‌کند؛ UI نمی‌تواند آن را override کند.
- همان preflight سمت سرور برای dry-run و live اجرا می‌شود. veto/heat/cash/concurrency/minimum/market status پیش از ایجاد intent اعمال می‌شوند.
- clientOrderId قطعی، ledger رزرو قبل از شبکه، امضای Ed25519 و عدم retry کور حفظ می‌شوند. timeout پس از ارسال به `unknown` می‌رود و نیازمند reconciliation است.
- پاسخ و audit فقط داده عمومی‌شده را دارند؛ raw body، signature و secret برگردانده نمی‌شوند.
- کارت owner وضعیت evidence را نشان می‌دهد و فقط پس از live mode و آماده بودن evidence دکمه ثبت را فعال می‌کند.

## پیامد

وجود endpoint به معنی فعال بودن live نیست. در این نسخه promotion واقعی انجام نشده، چون soak پنج‌روزه به محیط متصل نوبیتکس نیاز دارد. حالت پیش‌فرض همچنان disabled و W2 فقط disabled/dry-run را ذخیره می‌کند؛ ارتقای live باید بیرون از UI و پس از بازبینی evidence انجام شود.
