# ADR-0003: اتصال به API نوبیتکس و طراحی کلاینت صرافی

- **وضعیت:** پذیرفته‌شده — فقط-خواندنی پیاده‌سازی شد (Accepted, read-only path implemented)
- **تاریخ:** 2026-02-14
- **تصمیم‌گیرندگان:** معمار فنی
- **ADRهای مرتبط:** 0002، 0008، 0009
- **مرجع:** مستندات رسمی https://apidocs.nobitex.ir — آدرس پایه `https://apiv2.nobitex.ir`

---

## ۱. زمینه

ربات فقط از **API رسمی نوبیتکس** استفاده می‌کند. اندپوینت‌های فعلیِ پراستفاده (طبق مستندات رسمی):

### ۱.۱ داده عمومی بازار (بدون احراز هویت)
| کاربرد | اندپوینت | توضیح |
|---|---|---|
| آمار ۲۴ ساعته بازار (دنیای نمادها) | `GET /market/stats` | فهرست کامل جفت‌ها، حجم، آخرین قیمت |
| دفتر سفارش نسخه ۳ | `GET /v3/orderbook/{SYMBOL}` یا `symbol=all` | سطوح `[قیمت، مقدار]`، `lastTradePrice`؛ حدود ۳۰۰ درخواست/دقیقه |
| معاملات اخیر | `GET /v2/trades/{SYMBOL}` | جریان تیک‌ها برای سیگنال‌های حجمی |
| کندل‌های OHLC (فرمت UDF) | `GET /market/udf/history?symbol=BTCIRT&resolution={1,5,15,60,240,D}&from=<unix>&to=<unix>` | سازگار با TradingView UDF (`t,o,h,l,c,v`) |
| تنظیمات/دقت بازارها | اندپوینت‌های گزینه‌های سیستم | گام قیمت/مقدار هر بازار برای اعتبارسنجی سفارش |

### ۱.۲ حساب کاربری و معاملات (نیازمند احراز هویت)
| کاربرد | اندپوینت | توضیح |
|---|---|---|
| کیف‌پول‌ها / موجودی | `GET /v2/wallets` (قدیمی: `/users/wallets/balance`) | مبالغ آزاد/قفل |
| ثبت سفارش | `POST /market/orders/add` | نوع `buy\|sell`، اجرای `limit\|market` (پشتیبانی از Stop و OCO نیز)، **`clientOrderId` برای idempotency** |
| وضعیت سفارش | `POST /market/orders/status` / `GET /market/orders/list` | تطابق پرشدگی‌ها |
| لغو | `POST /market/orders/update-status` (لغو) / `cancel-batch` | کنترل چرخه‌حیات |

### ۱.۳ احراز هویت
دو روش پشتیبانی‌شده:
1. **توکن:** هدر `Authorization: Token <token>` (توکن نشست با عمر طولانی).
2. **کلید API (ترجیحی برای ربات):** هدرهای `Nobitex-Key` و `Nobitex-Signature` و `Nobitex-Timestamp`؛ متن امضا = `timestamp + METHOD + full_path + raw_body` با الگوریتم **Ed25519**. کلیدها **مجوزمند** هستند (دامنههای READ / TRADE) — ربات هرگز مجوز برداشت درخواست نمی‌کند.

## ۲. تصمیم

ساخت آداپتور نازک اختصاصی — `exchange/NobitexClient`:

1. **پشتیبانی از هر دو احراز هویت**، پیش‌فرض **کلید API با امضای Ed25519** و فقط مجوز READ+TRADE. کلیدها از متغیرهای محیطی (`NOBITEX_API_KEY`, `NOBITEX_API_SECRET`) خوانده می‌شوند؛ هرگز در مخزن کد commit نمی‌شوند.
2. **مدل‌های داخلی استاندارد** (`Symbol, Candle, OrderBook, Order, Trade, Balance`) تا کد استراتژی هیچ‌وقت با JSON خام فروشنده کار نکند.
3. **سیاست پایداری:** تایم‌اوت اتصال/خواندن (۳/۱۰ ثانیه)، Retry با Backoff نمایی + Jitter فقط برای **GET**ها؛ **سفارش‌ها هرگز کورکورانه تکرار نمی‌شوند** — idempotency با `clientOrderId` + تطابق وضعیت. بعد از N خطای متوالی، Circuit Breaker باز می‌شود و معامله متوقف می‌گردد.
4. **محدودیت نرخ:** Token Bucket سمت کلاینت برای هر کلاس اندپوینت؛ محافظت از Burst؛ کش آمار؛ تجمیع چندنمادی با `/v3/orderbook/all`.
5. **ایمنی ساعت:** بررسی انحراف ساعت با `Nobitex-Timestamp` و لاگ‌کردن آن.
6. **تست‌های قراردادی:** فیکسچرهای JSON ضبط‌شده برای هر اندپوینت؛ CI آداپتور را روی فیکسچرها تست می‌کند + تست دود اختیاری.
7. **رابط آداپتور `ExchangePort`** امکان افزودن صرافی دوم در آینده (برای داده جهانی مثل Funding/OI در FA) را میدهد.

## ۳. گزینه‌های بررسی‌شده

| گزینه | رأی |
|---|---|
| SDKهای کامیونیتی غیررسمی | رد: ریسک اعتماد و نگهداری؛ فقط مرور مرجع |
| اسکرپ وب‌سایت | رد: نقض شرایط استفاده و شکنندگی |
| Polling صرافی‌های جهانی برای سیگنال و نوبیتکس فقط برای اجرا (فاز ۳+) | پذیرفته‌شده به‌عنوان ارتقای اختیاری برای میجورها (با تصحیح پرمیوم) |

## ۴. پیامدها

**مثبت:** جداسازی از فروشنده، جریان سفارش idempotent، بودجه نرخ صادقانه، احراز هویت هم‌راستا با امنیت.
**منفی:** هزینه نگهداری ارتقاهای API بر عهده ماست (تسکین: تست قراردادی، پین نسخه‌ها، رصد Changelog).

## ۵. نکات عملیاتی

- لاگ متادیتای درخواست/پاسخ با پاک‌سازی امضا و اسرار.
- هر سفارش `clientOrderId` قطعی دارد = هش (شناسه سیگنال، نماد، سمت، سطل زمانی) → تلاش مجدد امن بدون سفارش تکراری.
- هنگام راه‌اندازی: واکشی سفارش‌های باز + موجودی‌ها؛ صرافی همیشه منبع حقیقت است؛ سپس سیگنال‌های جدید زمان‌بندی می‌شوند.

## اصلاحیه پیاده‌سازی — 2026-10-20

جدول §۲ قرارداد کامل API را تعریف می‌کند، نه آنچه کلاینت پیاده کرده است. امروز:

| گروه | وضعیت |
|---|---|
| `/market/stats`, `/v3/orderbook/{symbol}`, `/market/udf/history` | پیاده‌شده (`server/nobitex_client.py`) |
| `POST /market/orders/*` (ثبت/لغا/وضعیت سفارش) | **پیاده نشده** — کلاینت متدی برای ارسال سفارش ندارد |
| احراز هویت کلید API (`NOBITEX_API_KEY/SECRET`) | در `.env.example` فقط به‌عنوان فاز ۳ رزرو شده |

یعنی داشبورد امروز **فقط-خواندنی** است؛ این با دروازه‌های ارتقای ADR-0009 سازگار
است، نه نقض آن.
