# ADR-0039 — تب مدیریت و فعالیت کاربران فقط برای مالک

[English](../en/ADR-0039-owner-user-management-tab.md) · **فارسی**

**وضعیت:** پذیرفته — در ۱٫۴٫۱ پیاده شد
**تاریخ:** ۲۰۲۶-۱۰-۲۵

## تصمیم

- یک تب مستقل «کاربران» فقط پس از احراز session مالک در navigation ظاهر می‌شود؛ پنهان‌سازی UI کنترل امنیتی محسوب نمی‌شود و API نیز مستقل نقش را enforce می‌کند.
- فهرست کاربران، نقش، active بودن، آخرین ورود، نشست‌ها و دعوت‌ها از API واقعی خوانده می‌شوند. مالک می‌تواند نقش را تغییر دهد، حساب را فعال/غیرفعال کند، نشست‌ها را ببندد و دعوت بسازد/لغو کند.
- bearer API token دیگر به endpointهای مدیریت کاربر دسترسی ندارد؛ session مالک الزامی است. همه mutationها CSRF معتبر می‌خواهند.
- جدول append-only `user_activity` رویدادهای login/logout/register، تغییر کاربر، بستن نشست و ساخت دعوت را بدون password/token/invite code ثبت می‌کند.
- `GET /api/auth/activity` فقط مالک است، limit حداکثر ۵۰۰ و فیلتر اختیاری user_id دارد. تب ۲۰۰ رویداد جدید را نمایش می‌دهد.

## پیامد امنیتی

viewer/operator حتی با دست‌کاری DOM یا فراخوانی مستقیم API پاسخ 403 می‌گیرند؛ ناشناس و bearer token پاسخ 401 می‌گیرند. داده حساس نشست، hash رمز و کد دعوت در activity یا UI قرار نمی‌گیرد.
