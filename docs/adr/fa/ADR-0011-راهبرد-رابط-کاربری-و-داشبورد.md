# ADR-0011: راهبرد رابط کاربری و داشبورد

**فارسی** · [English](../en/ADR-0011-user-interface-and-dashboard-strategy.md)

- **وضعیت:** پذیرفته‌شده با اصلاحیه (Accepted, amended)
- **تاریخ:** 2026-02-14
- **تصمیم‌گیرندگان:** معمار فنی، مالک محصول
- **ADRهای مرتبط:** 0001، 0002، 0008، 0009
- **نمونه اولیه تعاملی:** `index.html` (ماک‌آپ فارسی راست‌به‌چپ، تک‌فایلی)

## ۱. زمینه

ربات خودکار معامله می‌کند، اما انسان باید بتواند (الف) وضعیت سیستم را در چند ثانیه بفهمد، (ب) حسابرسی کند که یک معامله چرا انجام شد، و (ج) در شرایط استرس، امن مداخله کند (کلیدهای اضطراری، توقف پانیک). رابط کاربری یک **اتاق فرمان** است نه آزمایشگاه تحلیل: پایش اول، کنترل دوم. باید روی دسکتاپ و موبایل کاربردی باشد، فارسی (راست‌به‌چپ) زبان اصلی و انگلیسی زبان دوم باشد، و هرگز اقدامات ناامن را سهوی در دسترس نگذارد.

## ۲. تصمیم — سه سطح رابط

### ۲.۱ سطح A — اتاق فرمان تحت وب (اصلی)
- **پشته:** بک‌اند FastAPI (از ADR-0002) + **SPA با React** (Vite، TypeScript) که به‌صورت استاتیک پشت API سرو می‌شود؛ نمودارها با **TradingView Lightweight Charts** (کندل، منحنی سرمایه) و **ECharts** (دونات، گیج)؛ استایل‌دهی با TailwindCSS.
- **بلادرنگ:** Server-Sent Events (SSE) برای به‌روزرسانی سرمایه/پوزیشن/سفارش (برای داشبوردِ بیشترِ یک‌طرفه، ساده‌تر و پایدارتر از WebSocket؛ اقدامات از طریق REST).
- **چندزبانه:** `fa` (راست‌به‌چپ، فونت وزیرمتن) پیش‌فرض؛ `en` اختیاری. نمایش دوگانه زمان (جلالی + Unix).
- **دسترسی:** احراز توکن تک‌اپراتور در نسخه ۱؛ گزینه انتشار فقط با لیست‌سفید IP / تونل SSH؛ هر اقدام کنترلی نیازمند تأیید مجدد (بخش ۲.۴).

### ۲.۲ سطح B — ربات تلگرام (عملیات صحرایی)
- هشدارها (پرشدگی‌ها، توقف‌ها، بریکرها، خلاصه روزانه) + **دستورات محدود:** `/status`, `/positions`, `/pnl today`, `/pause`, `/resume`, `/panic` (دو مرحله‌ای).
- لیست‌سفید شناسه کاربر؛ اقدامات حساس در لاگ حسابرسی داشبورد ثبت می‌شوند.

### ۲.۳ سطح C — Grafana (فقط زیرساخت)
- متریک‌های ماشین/API، تأخیر، نرخ خطا — عمداً رابط معاملاتی نیست.

## ۳. صفحات (معماری اطلاعات)

| صفحه | محتوا | هدف طراحی |
|---|---|---|
| **۱. اتاق فرمان** | منحنی سرمایه، سود/زیان امروز و کل، دمای ریسک باز، نرخ موفقیت، PF، نشان حالت (کاغذی/زنده)، پوزیشن‌های باز با سودزنده، دونات تخصیص سرمایه | درک ۵ثانیه‌ای: معناشناسی سبز/کهربایی/قرمز |
| **۲. کاوشگر سیگنال** | کاندیداهای رتبه‌بندی‌شده با میله امتیاز ترکیبی + تفکیک (TA/FA/LIQ)، پرچم هم‌راستایی MTA، مینی‌چارت کندل هر نماد، شواهد بازشونده «چرا این معامله» | حسابرسی کامل رتبه‌بندی (ADR-0007) |
| **۳. فاندامنتال** | امتیاز FA هر دارایی، وتوهای فعال (پرچم قرمز) با لینک شواهد، فید خبر با شدت (هک/دی‌لیست/آنلاک/...)، روند پرمیوم USDTIRT | شفافیت لایه کُند (ADR-0006) |
| **۴. سفارش‌ها و معاملات** | نمای زنده ماشین حالت سفارش (`PLANNED→...→CLOSED`)، پرشدگی‌ها با لغزش نسبت به میانی، فیلتر تاریخچه | تطابق UI ↔ وضعیت صرافی |
| **۵. کنترل‌های ریسک** | سقف‌های سبد با میله پیشرفت، وضعیت کلیدهای اضطراری (روزانه/هفتگی/متوالی)، پیش‌نمای حجم هر معامله، **دکمه پانیک نگه‌داری (۳ ثانیه، hold-to-confirm)** | اقدامات امنیتی محافظت‌شده، هرگز یک‌کلیک |
| **۶. آزمایشگاه بک‌تست** | فهرست اجراها بر اساس هش کانفیگ، کارت‌های متریک (PF, MDD, Sharpe و...)، نمودار Walk-Forward، نقشه حرارتی حساسیت پارامتر، مقایسه کاغذی↔بک‌تست | چرخه بازخورد تحقیق ↔ زنده |
| **۷. تنظیمات** | نمای YAML وزن‌ها با تاریخچه تغییرات (diff)، پرچم‌های ویژگی، سلامت ارائه‌دهندگان (نشان کهنگی)، وضعیت کلید API (فقط دامنه‌ها، هرگز خود کلید) | شفافیت کانفیگ بدون ریسک ویرایش |

## ۴. اصول UX

1. **وضعیت پیش از زیبایی:** حالت (کاغذی/زنده/متوقف) و وضعیت مسلح‌بودن کلید اضطراری همیشه در هدر دیده می‌شود.
2. **بدون خطای سهوی:** اقدامات مخرب با «نگه‌داشتن برای تأیید» (hold) و حلقه پیشرفت؛ دو مرحله‌ای در تلگرام.
3. **اعداد در اولویت:** تایپوگرافی عددی یکنواخت (tabular-nums)، ارقام فارسی، جداکننده هزارگان، رنگ‌بندی سازگار علامت (سود=زمردی، زیان=قرمز، صفر=خنثی).
4. **تم تیره معاملاتی:** پس‌زمینه رویتی تیره (zinc)، لهجات نئون، کنتراست بالا برای پایش شبانه.
5. **موبایل برای هشدار:** هر وضعیت بحرانی با حداکثر ۲ لمس از صفحه قفل قابل دسترس — از طریق لینک‌های عمیق تلگرام به صفحات داشبورد.
6. **اسکلت‌بار + نشان کهنگی:** هر داده قدیمی‌تر از N ثانیه، چیپ «کهنه» می‌گیرد — UI هرگز بی‌صدا غلط نمی‌ماند.

## ۵. الزامات امنیتی

- به‌صورت پیش‌فرض بدون انتشار عمومی: داشبورد روی localhost/تونل SSH یا شبکه خصوصی بایند می‌شود؛ پراکسی معکوس با احراز، اختیاری است.
- کلید API هرگز رندر نمی‌شود؛ فقط برچسب دامنه (`READ`, `TRADE`, `WITHDRAW: ناموجود`).
- صفحه لاگ حسابرسی همه اقدامات کنترلی را ثبت می‌کند (چه‌کسی/چه‌زمانی/چه‌چیزی/نتیجه).
- توکن نشست با انقضای کوتاه + رفرش؛ توکن CSRF برای عملیات تغییردهنده.

## ۶. گزینه‌های بررسی‌شده

| گزینه | رأی |
|---|---|
| Grafana به‌عنوان UI اصلی | رد: متریک عالی، UX ضعیف برای کنترل/حسابرسی دامنه |
| فقط تلگرام | رد: نمای غنی ندارد؛ به‌عنوان سطح همراه نگه داشته شد |
| قالب ادمین آماده | رد: ظاهر عمومی، وابستگی سنگین؛ سفارشی لاغرتر است |
| HTMX/رندر سمت سرور | پذیرفته به‌عنوان گزینه جایگزین فاز ۱ اگر هزینه ساخت SPA باید عقب بیفتد |
| Jupyter/Streamlit | رد: ابزار تحقیق‌اند، اتاق فرمان نیستند |

## ۷. تحویل‌ها و فازبندی

- **فاز ۱:** نمونه اولیه (ماک‌آپ `index.html`) ← FastAPI + SSE + اتاق فرمان + کنترل‌های ریسک (اولویت با بخش‌های عملیات-بحرانی).
- **فاز ۲:** کاوشگرهای سیگنال/FA، صفحه سفارش‌ها.
- **فاز ۳:** آزمایشگاه بک‌تست، diff تنظیمات، لینک‌های عمیق تلگرام، لوکال انگلیسی.

## ۸. پیامدها

**مثبت:** درک سریع موقعیت، توضیح‌پذیری سطح حسابرسی، الگوهای مداخله امن، UX بومی فارسی/راست‌به‌چپ.
**منفی:** SPA به CI/ابزار بیلد اضافه می‌کند — با فازبندی و گزینه HTMX تسکین می‌شود.

## اصلاحیه پیاده‌سازی — 2026-10-20: معماری اطلاعات فعلی

جدول §۳ هفت صفحه را تعریف کرد؛ داشبورد امروز **ده** تب دارد. سه تای زیر بعد از آن
اضافه شدند و باید بخشی از این ADR شمرده شوند:

| تب تازه | چرا اضافه شد | نکتهٔ طراحی |
|---|---|---|
| **گزارش عملکرد** (`performance`) | ADR-0012 به یک صفحهٔ مستقل برای MSI، نرخ برد، IC و کالیبراسیون نیاز داشت | تا وقتی نمونه‌ای نیست، هر کاشی جمله می‌گوید نه «—» |
| **میز دستی** (`desk`) | ADR-0013 اجرای ترکیبی را تعریف کرد و به یک نقطهٔ ورود انسانی نیاز داشت | بلیط + صف تأیید با TTL |
| **لاگ خطاها** (`errors`) | خطاهای گرید و اگرید بدون ثبت، نامرئی بودند | چهار دکمهٔ آن هر کدام یک اثر دیدنی دارند |

دو تغییر دیگر که در متن اصلی نبود:

- **تنظیمات فقط-خواندنی است** به‌جز تنظیمات همین مرورگر (زبان، بازه‌ها). هیچ کلید یا
  توکنی از UI نوشته نمی‌شود — مرز امنیتی، نه نقص.
- **ناوبری موبایل** همهٔ ده تب را دارد؛ قبلاً تب تنظیمات در موبایل اصلاً دیده نمی‌شد.

قاعدهٔ ADR-0014 بر همهٔ این صفحه‌ها حاکم است: هر پنل یا عدد دارد، یا جمله، یا
«چیزی برای نمایش نیست» — «—» تنها پذیرفته نیست.
