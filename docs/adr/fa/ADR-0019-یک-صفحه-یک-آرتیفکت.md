# ADR-0019: یک صفحه، یک آرتیفکت — نه یک نسخهٔ موبایل و یک نسخهٔ دسکتاپ

[English](../en/ADR-0019-one-page-one-artifact.md) · **فارسی**

- **وضعیت:** پذیرفته و پیاده‌شده
- **تاریخ:** ۲۰۲۶-۱۰-۲۲
- **صاحب تصمیم:** کارفرما (پرسش مستقیم: «چرا دو نسخه با این همه تعارض؟»)
- **مرتبط:** ۰۰۱۶ (دروازه‌های ایستا و CI)، ۰۰۱۷ (بررسی از داخل داشبورد)
- **نگهبان:** `server/tests/test_single_page.py`، `scripts/build_standalone.py`،
  `npm run build` + `git diff --exit-code -- nobitex-mobile.html` در CI

---

## ۱. مسئله

دو فایل HTML در مخزن هست:

```
index.html            ۶٬۰۲۱ خط — نشانه‌گذاری + لینک ۵ استایل و ۲ اسکریپت
nobitex-mobile.html  ۱۰٬۰۶۴ خط — همان صفحه با همان ۷ فایل به‌صورت درون‌خطی
```

از بیرون شبیه «دو نسخه» است، و همین ظاهر یک ترس درست می‌سازد: تعارض، دوباره‌کاری، و
رفع‌شدنِ یک باگ در یکی و نه در دیگری. پرسش کارفرما این بود که چرا دو نسخه داریم و
پیشنهادش این بود که یک نسخهٔ کاملاً ریسپانسیو بمانَد.

## ۲. تصمیمی که در واقع گرفته شده بود

`nobitex-mobile.html` **دست‌نویس نیست**. `scripts/build_standalone.py` آن را از
`index.html` + پنج فایل CSS + `nbx-core.js` + `nbx-app.js` می‌سازد و تنها کاری که
می‌کند درون‌خطی‌کردن است: حذف `<link>`ها، حذف فونت CDN، حذف `manifest.json`، و
جای‌گذاری `<style id="nbx-standalone-css">` و دو `<script id="nbx-inline-…">`.

اندازه‌گیری این تصمیم را تأیید می‌کند: با برگرداندنِ همان درون‌خطی‌سازی، دو فایل
**دقیقاً** یکی می‌شوند (تفاوت فقط خط‌های خالیِ باقی‌مانده از حذف `<link>`ها است). پس
«نسخهٔ موبایل» وجود ندارد؛ **یک صفحهٔ ریسپانسیو** وجود دارد به‌علاوهٔ یک **آرتیفکت
تولیدشده** از همان صفحه.

آن آرتیفکت لازم است، و دلیلش هم دقیقاً همان چیزی است که کارفرما از آن شکایت داشت —
پیش‌نمایش روی موبایل. در این بافت‌ها زیرمنبع اصلاً بارگذاری نمی‌شود:

- فایلی که از `file://` یا `content://` باز می‌شود (پوشهٔ دانلود گوشی)
- iframe پیش‌نمایش با `sandbox="allow-scripts"` و بدون شبکه
- میزبان air-gapped

در هر سه، نسخهٔ پیوندی با CSS و JS صفر می‌رسد: بدون چارت، بدون داده.

## ۳. تصمیم

1. **`index.html` تنها منبع است.** نشانه‌گذاری، استایل و منطق فقط این‌جا نوشته می‌شود.
   ریسپانسیو بودن با واریانت‌های Tailwind (`sm:`/`md:`) و
   `injectMobileNavAndDownload()` انجام می‌شود، نه با یک سند دوم.
2. **`nobitex-mobile.html` آرتیفکت است، نه نسخه.** هرگز دستی ویرایش نمی‌شود؛
   تغییر در آن با بیلد بعدی پاک می‌شود، پس تفاوت آن با منبع **همیشه** یعنی نقص.
3. **تعارض ساختاراً ممکن نیست.** CI و انتشار هر دو با
   `git diff --exit-code -- nobitex-mobile.html` شکست می‌خورند اگر آرتیفکت از منبع
   عقب باشد؛ و `server/tests/test_single_page.py` بدون نیاز به node، خودِ برابری را
   می‌سنجد.
4. **نام تاریخی است و تغییر نمی‌کند.** آدرس `/download/nobitex-mobile.html` و
   `filename="nobiTrader-mobile.html"` در مستندات و تست‌ها زیاد ارجاع داده شده‌اند؛
   تغییرشان ریسکِ لینک شکسته را بدون هیچ سود فنی اضافه می‌کند. مستندسازی صریح
   (همین سند) جای تغییر نام را می‌گیرد.

## ۴. پیامدها

- یک باگ فقط یک‌جا رفع می‌شود، و هر دو بافت آن را می‌گیرند.
- افزودن یک کلاس Tailwind تازه نیاز به `npm run css` دارد، وگرنه کلاس در CSS نهایی
  نیست؛ `build_standalone.py` پیش از درون‌خطی‌کردن با
  `check_css_freshness()` جلوی این را می‌گیرد.
- هزینه: یک آرتیفکت ۱۰ هزار خطیِ کامیت‌شده. پذیرفته شده، چون دانلود آفلاین برای گوشی
  یک قابلیت است، نه یک باقی‌مانده.
- اگر روزی آرتیفکت لازم نبود: کافی است `build_standalone.py` و نگهبان‌هایش حذف شوند؛
  `index.html` بدون هیچ تغییری سرورش را ادامه می‌دهد. یعنی این تصمیم **برگشت‌پذیر** است.

## ۵. دو لایهٔ آیکون (تصحیح یک تشخیص غلط)

در بررسی همین پرسش این‌طور به‌نظر رسید که داشبورد تابع `setCoinMetadata` را تعریف
می‌کند ولی هرگز صدا نمی‌زند. **این غلط بود.** تعریف در `index.html` است، ولی
فراخوانی در `nbx-app.js` است:

```js
await NBX.boot();
loadCoinMetadata();                                  // پر کردن لوگوهای آنلاین
setInterval(loadCoinMetadata, 60 * 60 * 1000);       // هر ساعت
```

و `index.html` همان `nbx-app.js` را بارگذاری می‌کند. آن خطی که در
`nobitex-mobile.html` دیده شد، نسخهٔ درون‌خطیِ همان فایل بود، نه یک جادو.

پس هر دو لایه زنده‌اند، همان‌طور که کارفرما گفت: SVGهای محلی (۴۰ فایل، base64، بدون
شبکه) و لوگوهای CoinGecko از مسیر سرور (`/api/coins` و `/api/coins/{id}/logo`،
کش دیسکی، TTL ۲۴ ساعت). آن ۱۰ کوینی که SVG محلی ندارند — TON, SHIB, NEAR, AXS,
EGLD, HBAR, APT, ARB, OP, PEPE — توسط همین لایهٔ دوم پوشش داده می‌شوند. برای این‌که
حذفِ آن فراخوانی بی‌صدا نمانَد،
`test_the_dashboard_asks_for_online_coin_metadata` اضافه شد.
