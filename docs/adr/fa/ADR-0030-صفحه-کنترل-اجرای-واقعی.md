# ADR-0030 — صفحهٔ کنترل اجرای واقعی: مشاهده و لغو پیش از route ثبت

[English](../en/ADR-0030-live-control-plane.md) · **فارسی**

**وضعیت:** پذیرفته‌شده — primitiveهای مرحله B3 در ۱٫۲٫۳ پیاده شد؛ routeها هنوز خاموش
**تاریخ:** ۲۰۲۶-۱۰-۲۵
**مرتبط:** ADR-0027، ADR-0028، ADR-0029

## زمینه

پیش از اینکه ثبت سفارش واقعی از API برنامه در دسترس باشد، اپراتور باید بتواند سفارش‌های صرافی را بخواند، وضعیت intent ثبت‌شده را reconcile کند و سفارش را با `clientOrderId` لغو کند. عرضهٔ route ثبت پیش از این کنترل‌ها، خروج از معامله را از ورود ضعیف‌تر می‌کند.

## نیازمندی‌ها

1. فهرست سفارش‌ها فقط خواندنی و با query string دقیقاً امضاشده باشد.
2. لغو فقط برای `clientOrderId` موجود در ledger مجاز باشد.
3. timeout لغو به `cancel-unknown` برسد و لغو کور تکرار نشود.
4. پاسخ قطعی به `canceled` یا `cancel-rejected` برسد و در ledger بماند.
5. secret و متن خام خطای transport ذخیره نشود.
6. route ثبت واقعی تا تکمیل کنترل نقش، preflight و audit در مرحله بعد خاموش بماند.

## تصمیم

ابتدا primitiveهای `list_orders` و `cancel` به کلاینت مستقل افزوده می‌شوند و با sender ساختگی آزمون می‌شوند. routeهای FastAPI و اتصال UI در تغییر جداگانه فقط پس از اثبات fail-closed بودن این primitiveها اضافه خواهند شد.

## پذیرش

- list مسیر کامل همراه query را امضا و GET بدون body بفرستد؛
- cancel شناسه ناشناخته را پیش از شبکه رد کند؛
- timeout یک attempt بسازد و retry دوم شبکه را صدا نزند؛
- پاسخ موفق وضعیت canceled و پاسخ ناموفق cancel-rejected بسازد.
