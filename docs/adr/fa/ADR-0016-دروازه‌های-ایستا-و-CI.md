## ۱. زمینه

پیش از این تصمیم، هیچ دروازهٔ ایستایی وجود نداشت. نه ruff بود، نه mypy، نه eslint،
نه CI. ۲۷۸ تست سبز بودند و هم‌زمان:

- **۲۷۷** یافتهٔ ruff — ۵۳ تایش `# noqa` که کدش دیگر انتخاب نمی‌شد، ۴۱ ایمپورت
  نامرتب، ۳۱ ایمپورت بلااستفاده، ۳۰ `datetime.timezone.utc`، ۲۶ annotation
  در گیومه،
- **۸۰** خطای mypy در ۱۳ فایل،
- **۲۹** خطای eslint — ۲۵ در بلوک ۴٬۰۰۰ خطی `index.html` که هیچ ابزاری نمی‌خواند
  و ۴ در دو باندل،

و ۲۷۸ تست سبز. این اعداد با همان کانفیگی که همین ADR تحویل می‌دهد، روی والدِ
`18e7a2f` بازتولید می‌شوند:

```
git worktree add /tmp/pre 18e7a2f~1
cp pyproject.toml /tmp/pre/ && cd /tmp/pre && ruff check server scripts && mypy
```

نسخهٔ اول این ADR عددهای ۲۵۵ / ۷۴ / ۱۹۷ را داشت. آن‌ها در نقاط مختلف کار
اندازه‌گیری شده بودند، نه از یک وضعیت قابل بازتولید، و عدد ۱۹۷ اصلاً بازتولید
نشد؛ اینجا اصلاح شده‌اند نه پاک.

هزینهٔ این نبود، در همان جایی پرداخت شد که باگ‌ها می‌آمدند: **درزهای عرضی**. چهار
نمونه که هر چهار پیش از این «سبز» بودند — و دقت کن هر کدام کجا گرفته شد: فقط
مورد چهارم از همین دروازه‌ها آمد؛ سه مورد دیگر از تست‌های invariant (ADR پیشین)،
از بازنویسی پول، و از probe زنده. پیام کامیت `18e7a2f` هر چهار را به دروازه‌ها
نسبت داده و آن نسبت‌دادن غلط است؛ این جمله جایش را می‌گیرد.

1. `main.py` مسیر `auto_tick` هنوز `equity_quote = eq * fx if fx else eq` داشت:
   بدون نرخ ارز، موجودی دلاری به‌جای تومان خوانده می‌شد و سفارش خودکار ده برابر
   بزرگ می‌شد.
2. `_position_payload` مقدار تومانی را از `from_api` می‌گذراند (که آن را ریال
   می‌خواند) و `value_usd` ده برابر کوچک‌تر می‌شد — همان ده‌برابری، این بار از
   تابعی که برای جلوگیری از آن نوشته شده بود.
3. `let candleSeries, lastCandle;` در `index.html` اعلام می‌شد و در `nbx-app.js`
   نوشته می‌شد. وقتی یک تحلیل‌گر آن را «متغیر بلااستفاده» دید و حذف شد، نوشتن در
   فایل دیگر به `ReferenceError` تبدیل شد که داخل `catch (e) {}` بلعیده می‌شد و
   چیپ «آخرین قیمت» بی‌صدا روی «—» ماند.
4. سه جدول ترجمه کلید تکراری داشتند؛ کلید دومی کلید اولی را بی‌صدا بازنویسی
   می‌کرد (`perf.origin` دو ترجمهٔ متفاوت داشت).

## ۲. تصمیم

سه دروازه، همه در CI، همه قرمز کردن build:

| ابزار | دامنه | چه چیزی را می‌گیرد |
|---|---|---|
| `ruff` | `server/`، `scripts/` | ایمپورت بلااستفاده/نامرتب، نام تعریف‌نشده، مقایسهٔ شرطی، `zip` بدون `strict` |
| `mypy` | `server/` (۳۵ فایل) | `None` که به حساب می‌آید، `dict[str, object]` که عدد فرض می‌شود |
| `eslint` | `nbx-core.js`، `nbx-app.js`، `scripts/*.js`، **و بلوک درون‌خطی `index.html`** | نام تعریف‌نشده، کلید تکراری، متغیر مرده |

بلوک درون‌خطی `index.html` از راه `scripts/lint_dashboard.mjs` استخراج و با همان
کانفیگ lint می‌شود؛ شماره خط گزارش‌شده همان شماره خط در `index.html` است.

### آنچه عمداً فعال نشد

- **`E501` (طول خط).** ۹۷ خط در `server/` بلندتر از ۱۰۰ ستون است (شمارش دوباره:
  `awk 'length>100' $(find server -name '*.py')`)؛ کوتاه‌کردنشان یک کامیت تماماً
  فضای سفید می‌شد که `git blame` را بی‌فایده می‌کند. `line-length = 100` تنظیم
  است تا فرمت‌کنندهٔ آینده همان را تولید کند.
- **`BLE001` / `S110` (`except Exception`، `pass`).** حلقه‌های polling عمداً
  `Exception` می‌گیرند: یک تیک خراب نباید سوکت را بکشد. جای ثبت خطا `errorlog`
  است. توضیح هر مورد به‌صورت کامنت سرِ جای خودش مانده است.
- ~~**`--check-untyped-defs`**~~ **اکنون فعال است** (بند ۵). فعال‌کردنش ۹۰ یافته
  داد: ۴ در `server/main.py` (یک لیست `rows` تایپ‌نشده باعث می‌شد sort و join
  قابل‌بررسی نباشند؛ حالا annotate شده) و ۸۶ در فیک‌های تست. هر فایل تست با یک
  directive در خط اول خودش معاف است؛ هر ماژول سرور بدنه‌به‌بدنه بررسی می‌شود.

## ۳. پیامدها

- **مثبت:** ۲۷۷ + ۸۰ + ۲۹ یافته به صفر رسید. `nobitex-mobile.html` (فایل
  تولیدشده) در CI با منبع مقایسه می‌شود تا از هم جدا نیفتند.
- **منفی:** هر ایمپورت بلااستفادهٔ تازه build را قرمز می‌کند. عمدی است.
- **شکننده:** قواعد `no-undef` در eslint نیاز به فهرست صریح گلوبال‌های صفحه دارد.
  هر نام مشترک تازه باید در `eslint.config.mjs` اعلام شود؛ این بهتر از خاموش‌کردن
  قاعده است، ولی یک قدم نگهداری اضافه می‌کند.

## ۴. شاهد

اندازه‌گیری روی `main` در کامیتی که این بازنگری را دارد (۲۰۲۶-۱۰-۲۰):

```
ruff check server scripts      → All checks passed
mypy                           → Success: no issues found in 35 source files
npm run lint                   → clean
npm run lint:dashboard         → 0 error(s) in 1 inline block
pytest server/tests            → 304 passed
```

سه job در `.github/workflows/ci.yml`: `python` (ruff/mypy/pytest)، `js` (eslint،
برابری بروکر، برابری preflight، تازگی فایل تولیدشده)، `ui` (۴۴ پنل روی فیکسچر
صرافی، self-test طبقه‌بند، و اسموک jsdom).

اسموک jsdom (`scripts/ui_smoke_test.js`) پیش از این دستی اجرا می‌شد. دلیل
بیرون‌ماندنش دو assertion بود که دنیایی را توصیف می‌کردند که این پروژه دیگر
ندارد — بنر «کندل شبیه‌سازی‌شده» در صفحهٔ عملکرد. هر دو با assertionهایی عوض
شدند که در همهٔ حالت‌ها برقرارند: نشان MSI باید با تعداد نمونه‌ای که کنارش
می‌نویسد بخواند، `#perfWarn` تنها وقتی می‌تواند دیده شود که حرفی دارد، و چیپ
منبع داده هرگز نباید به یک عدد لخت تبدیل شود.

## ۵. آنچه دروازه‌ها پوشش نمی‌دهند

- **`check_untyped_defs` برای `server/` روشن، برای فایل‌های تست خاموش.** فیکِ
  تستی‌ای که عمداً `None` می‌دهد، به pytest جواب می‌دهد نه به mypy. directive در
  خط اول هر فایل تست است؛ در همان diffی که تست را اضافه می‌کند دیده می‌شود.
- **فرمت‌کننده‌ای اجرا نمی‌شود.** `ruff format` تنظیم است (`line-length = 100`)
  ولی اعمال نمی‌شود؛ اضافه‌کردنش الان فایل‌هایی را بازنویسی می‌کرد که هدف این ADR
  تثبیتشان است.
- **کف پوشش تست نداریم.** پوشش گزارش می‌شود (۸۵٪) ولی افت آن CI را قرمز نمی‌کند.
- **eslint نحو و نام‌ها را می‌بیند، نه رفتار را.** پنلی که عدد غلط نشان دهد از
  lint رد می‌شود؛ چیزی که آن را می‌گیرد `probe_live.py` و اسموک jsdom است.
