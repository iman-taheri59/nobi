# ADR-0029 — کلاینت اجرای قابل‌بازیابی: dry-run، idempotency و وضعیت نامعلوم

[English](../en/ADR-0029-recoverable-execution-client.md) · **فارسی**

**وضعیت:** پذیرفته‌شده — مرحله B2 در ۱٫۲٫۲ پیاده شد؛ route عمومی و live همچنان خاموش
**تاریخ:** ۲۰۲۶-۱۰-۲۵
**مرتبط:** ADR-0008، ADR-0009، ADR-0014، ADR-0027، ADR-0028

## زمینه

امضای درست برای اجرای واقعی لازم است ولی کافی نیست. خطر اصلی، timeout پس از رسیدن درخواست به صرافی است: برنامه نمی‌داند سفارش ثبت شده یا نه و retry کور می‌تواند سفارش دوم بسازد. `clientOrderId` نوبیتکس در سفارش‌های باز یکتا و برای وضعیت/لغو قابل استفاده است؛ پس باید پیش از شبکه ساخته و پایدار ثبت شود.

## نیازمندی‌ها

1. حالت پیش‌فرض `disabled` باشد؛ `dry-run` شبکه را صدا نزند؛ `live` علاوه بر تنظیم، عبارت تأیید صریح بخواهد.
2. هر intent یک idempotency key اجباری داشته باشد و از آن `clientOrderId` معتبر و حداکثر ۳۲ نویسه ساخته شود.
3. raw JSON نهایی و شناسه پیش از نخستین درخواست در SQLite ثبت شوند.
4. تکرار همان key و همان payload درخواست دوم نسازد؛ همان رکورد را برگرداند.
5. همان key با payload متفاوت conflict و fail-closed باشد.
6. timeout/خطای مبهم وضعیت `unknown` بسازد و هرگز خودکار سفارش را retry نکند.
7. خروج از `unknown` فقط با reconciliation از endpoint وضعیت بر اساس `clientOrderId` باشد.
8. secret در ledger، خطا، repr یا پاسخ dry-run ذخیره نشود.
9. این مرحله route کاربری تازه یا اتصال خودکار موتور سیگنال به live ایجاد نکند.

## تصمیم

`server/live_execution.py` یک مرز مستقل شامل `ExecutionMode`، `OrderIntent`، `ExecutionLedger` و `LiveExecutionClient` می‌سازد. caller یک sender تزریق می‌کند؛ تست‌ها کاملاً بدون شبکه‌اند. signer ADR-0028 فقط در حالت live و درست پیش از ارسال فراخوانی می‌شود.

حالت‌های پایدار: `prepared`، `dry-run`، `accepted`، `rejected`، `unknown` و `reconciled`. رکورد `unknown` قابل retry ثبت سفارش نیست؛ فقط reconcile مجاز است.

## معیار پذیرش

- disabled و live بدون عبارت تأیید پیش از شبکه رد شوند؛
- dry-run هیچ senderای را صدا نزند؛
- دو فراخوانی یک intent فقط یک attempt داشته باشند؛
- payload متفاوت با key یکسان رد شود؛
- timeout به unknown برسد و تکرار آن send نکند؛
- reconcile با `clientOrderId` رکورد را به وضعیت قطعی ببرد؛
- تمام آزمون‌های قبلی سبز بمانند.
