# ADR-0034 — بستهٔ عملیاتی soak: پشتیبان کامل و snapshot روزانه

[English](../en/ADR-0034-soak-operations-pack.md) · **فارسی**

**وضعیت:** پذیرفته‌شده — B6 در ۱٫۲٫۷ پیاده شد
**تاریخ:** ۲۰۲۶-۱۰-۲۵
**مرتبط:** ADR-0027، ADR-0033

## زمینه

دروازهٔ شواهد بدون عملیات پایدار کافی نیست. `live_execution.db` تا امروز در backup نبود و مشاهدهٔ روزانهٔ evidence به اجرای دستی curl وابسته بود. soak پنج‌روزه باید بعد از restart و restore قابل ادامه و با CSV بدون secret قابل ممیزی باشد.

## تصمیم و نیازمندی‌ها

1. قالب backup نسخه ۲ شامل journal، auth و live execution است؛ `.env` و credential همچنان حذف‌اند.
2. restore قالب قدیمی نسخه ۱ را می‌پذیرد و در آن حالت live DB موجود را دست نمی‌زند.
3. هر دیتابیس پیش از جایگزینی checksum و `PRAGMA integrity_check` می‌شود.
4. ابزار snapshot فقط GET به health و live/evidence می‌زند و token را فقط از environment می‌خواند.
5. CSV فقط دادهٔ تجمیعی، نسخه، mode، samples/days/ambiguity، state counts و readiness را ثبت می‌کند.
6. پاسخ ناموفق یا ناقص هیچ ردیفی ایجاد نمی‌کند.

## پذیرش

- round-trip هر سه دیتابیس را بازگرداند؛
- archive دستکاری‌شده پیش از تغییر مقصد رد شود؛
- archive نسخه ۱ restore شود و live مقصد را تغییر ندهد؛
- snapshot موفق یک header و یک row بسازد؛ شکست فایل را تغییر ندهد؛
- token در CSV، stdout یا exception ذخیره نشود.
